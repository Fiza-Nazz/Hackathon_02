# Data Model: AI-Native Todo Application Phase II

## User Entity

### Attributes
- **id**: UUID (required, unique, auto-generated)
  - Primary identifier for the user
  - UUID for secure global uniqueness
  - Generated automatically when a user is created

- **email**: String (required, unique)
  - User's email address for authentication
  - Must be valid email format
  - Maximum length: 255 characters
  - Used for login and identification

- **password_hash**: String (required)
  - Hashed password for secure authentication
  - Never stored as plain text
  - Generated using secure hashing algorithm

- **created_at**: DateTime (required)
  - Timestamp when the user account was created
  - Automatically set during account creation
  - Used for account management

- **updated_at**: DateTime (required)
  - Timestamp when the user account was last updated
  - Automatically updated when user data changes
  - Used for tracking account changes

### Validation Rules
- Email must be valid email format
- Email must be unique across all users
- Email must be between 5 and 255 characters
- Password must meet security requirements (handled by Better Auth)

### Relationships
- **tasks**: One-to-many relationship with Task entity (one user to many tasks)

## Task Entity

### Attributes
- **id**: UUID (required, unique, auto-generated)
  - Primary identifier for the task
  - UUID for secure global uniqueness
  - Generated automatically when a task is created

- **title**: String (required)
  - The main text of the task
  - Must not be empty or null
  - Maximum length: 255 characters

- **description**: String (optional)
  - Additional details about the task
  - Can be null or empty string
  - Maximum length: 1000 characters

- **completed**: Boolean (required)
  - Indicates whether the task is completed
  - Default value: false (incomplete)
  - Can be toggled between true and false

- **user_id**: UUID (required, foreign key)
  - Reference to the user who owns this task
  - Ensures multi-user data isolation
  - Links to User.id

- **created_at**: DateTime (required)
  - Timestamp when the task was created
  - Automatically set during task creation
  - Used for sorting and tracking

- **updated_at**: DateTime (required)
  - Timestamp when the task was last updated
  - Automatically updated when task data changes
  - Used for tracking modifications

### Validation Rules
- Title must be provided (not empty or null)
- Title must be between 1 and 255 characters
- Description, if provided, must be between 1 and 1000 characters
- ID must be unique within the task collection
- user_id must reference an existing user
- Only the task owner can modify the task

### State Transitions
- **Creation**: New task is created with `completed = false` and assigned to user
- **Update**: Task attributes (title, description) can be modified by owner
- **Toggle Completion**: `completed` status toggles between true/false by owner
- **Deletion**: Task is removed from the collection by owner

## Session Entity (for authentication)

### Attributes
- **id**: UUID (required, unique, auto-generated)
  - Primary identifier for the session
  - UUID for secure global uniqueness

- **user_id**: UUID (required, foreign key)
  - Reference to the user this session belongs to
  - Links to User.id

- **token**: String (required, unique)
  - JWT token string for session identification
  - Generated by Better Auth

- **expires_at**: DateTime (required)
  - Timestamp when the session expires
  - Used for automatic session invalidation

- **created_at**: DateTime (required)
  - Timestamp when the session was created

### Validation Rules
- token must be unique across all sessions
- expires_at must be in the future
- user_id must reference an existing user

### Relationships
- **user**: Many-to-one relationship with User entity (many sessions to one user)

## Database Schema Constraints

### Multi-user Data Isolation
- All task operations must be filtered by user_id to ensure users can only access their own tasks
- Foreign key constraints ensure referential integrity between User and Task entities
- Database-level security prevents cross-user data access

### Indexes
- User.email: Unique index for fast authentication lookups
- Task.user_id: Index for efficient user-specific queries
- Session.token: Unique index for fast session validation
- Task.created_at: Index for chronological sorting

### Security Constraints
- Passwords stored as hashed values only (never plain text)
- Session tokens stored securely with expiration tracking
- Automatic cleanup of expired sessions
